# src/SharpCpp.Rendering/

## Responsibility

The Rendering layer owns **code generation**: it transforms a finalized `BindingCompilation` (the complete type/member graph from the Model layer) into compilable C# and C++ source files. This is the terminal stage in the SharpCpp pipeline — everything upstream (metadata, parsing, pipeline passes) converges here to produce the actual binding glue.

Key architectural rule: **the renderer is stateless and pure**. `BindingOutputRenderer.Render()` takes a `BindingCompilation` and returns a `GeneratedBindingSet`; it has no mutable state, no I/O, and no dependency on any other layer except `SharpCpp.Model`.

## Design Patterns

**Template-based rendering.** Every model type (`RecordBinding`, `FunctionBinding`, `EnumBinding`, `FieldBinding`) has a dedicated private rendering method (e.g. `RenderRecord()`, `RenderManagedProperty()`, `RenderNativeDirectorClass()`). These methods use C# raw string interpolation (`$$"""…"""`) to emit text. There is no template language or external template engine — the renderer is a collection of ~30 string-composing functions.

**Partial-class decomposition.** Each generated C# binding class is split into two partial declarations:
- The outer class (public API: constructors, methods, properties, operators, virtual callbacks)
- An inner `__PInvoke` partial class (all `[LibraryImport]` P/Invoke declarations)

This keeps the public surface clean while isolating the native interop contract.

**Group-based file splitting.** When a `deriveGroupStem` delegate is provided, output is partitioned by header include path. Each group generates a pair of files (`{headerStem}.g.cs` + `{headerStem}.g.cpp`) plus a shared `{fileStem}.Bindings.Aliases.g.cs`. Without grouping, the output is monolithic (`{fileStem}.Bindings.g.cs`, `{fileStem}.Bindings.g.cpp`, `{fileStem}.Bindings.Aliases.g.cs`).

**Director pattern for virtual dispatch.** For polymorphic C++ classes, a C++ *director class* is generated that inherits from the native type and overrides every virtual method. Each override checks an unmanaged function pointer field; if set, it forwards the call to the managed side through that callback. The `ConnectDirector()` method on the C# side passes function pointers for each virtual slot. The C# side uses `HasManagedOverride()` (reflection) to decide whether to supply a pointer or `null` — when `null`, the director calls the base C++ implementation.

**Runtime generic dispatch.** Generic C++ records/functions are pre-instantiated at compile time for every supported type argument combination. The C# side uses `typeof(T) == typeof(int)` chains at runtime to select the correct pre-instantiated native entry point. This avoids generic sharing in the native ABI while presenting a natural C# generic API.

**Clean-write output.** `GeneratedBindingSet.WriteToDirectory()` enumerates the target directory for stale `*.g.cs` / `*.g.cpp` files before writing. Any file that was generated in a previous build but is no longer in the current output set is deleted. This prevents orphaned binding code from accumulating.

## Data & Control Flow

### Entry Point

```
BindingOutputRenderer.Render(BindingCompilation, fileStem, deriveGroupStem?)
  → GeneratedBindingSet
```

1. **Assign import method names.** `AssignImportMethodNames()` walks all free functions and record members, deduplicating overloaded ManagedName values by appending numeric suffixes (`Foo`, `Foo2`, `Foo3`). This ensures unique `[LibraryImport]` method identifiers.

2. **File set construction.**
   - **Without grouping:** three files directly (C# bindings, C++ bindings, aliases).
   - **With grouping:** members are partitioned by `deriveGroupStem(headerIncludePath)`. Each group produces a C#/C++ pair. An additional `Aliases.g.cs` file is generated with the `includeRegistry: true` flag.

3. **Managed C# rendering** (`RenderManagedBindings`):
   - Writes `// <auto-generated />`, `#nullable enable`, `using System.Runtime.InteropServices`
   - Groups records and enums by `ManagedNamespace`; emits one `namespace {…}` block per namespace
   - Within each namespace: interfaces → records → enums (alphabetized)
   - Each record emits: constructor(s) → accessor properties → instance methods → static methods → operators → fields → dispose logic → `__PInvoke` inner class
   - Interface records and enums get dedicated rendering (`RenderInterface`, `RenderEnum`)
   - Polymorphic records implement `INativeObjectRegistration<T>` with static type metadata
   - Free functions (not inside any record) go into a top-level static class (`compilation.ManagedClassName`)
   - Virtual methods and callbacks use `[UnmanagedFunctionPointer]` delegates stored as cached `nint` pointers

4. **Native C++ rendering** (`RenderNativeBindings`):
   - Writes `#include` directives for all SharpCpp support headers + parsed C++ headers
   - Emits **director classes** for polymorphic records (one class per record with virtual slots)
   - Emits **callbase helper entry points** for non-pure-virtual methods (allow managed calling `base.Method()`)
   - Emits **generic instantiations**: constructors, instance methods, static methods, delete per type-argument combination
   - Emits **free function entry points** → `SHARPCPP_EXPORT ret_t<T> entrypoint(params) { MarshallerInvoker::invoke_as<FT>(…) }`
   - Emits **instance method entry points** (same structure with `self` pointer)
   - Emits **static method entry points**
   - Emits **constructor entry points** → `MarshallerInvoker::construct<T>(args)`
   - Emits **field accessor entry points** (get/set via `MarshallerInvoker::get_field`/`set_field`)
   - Emits **delete thunks** → `MarshallerInvoker::destroy<T>(self)`
   - Emits **type metadata entry points** for polymorphic types (`typeid().hash_code()`)
   - All entry points use the `SHARPCPP_EXPORT` macro for shared-library visibility

5. **Alias rendering** (`RenderAliasBindings`):
   - Generates the `__NativeObjectRegistryInitializer` class that registers all polymorphic concrete types with `NativeObjectRegistry.RegisterType<T>()`

6. **Generic rendering** (`BindingOutputRenderer.Generic.cs`):
   - Pattern-matches generic type arguments at runtime using `typeof(T) == typeof(int)` conditions
   - Each branch dispatches to a pre-instantiated `[LibraryImport]` entry point
   - Type substitution (`SubstituteGenericType`) recursively walks `BindingType` trees, replacing generic parameters with concrete type arguments
   - Native generic entry points use `MarshallerInvoker::invoke<T>(&ConcreteType::method, self, args)`

7. **Output.** `GeneratedBindingSet.WriteToDirectory(outputPath)` prunes stale `*.g.cs`/`*.g.cpp` files, creates directories, and writes all generated content.

## Integration Points

### Dependencies (consumed by this layer)

| Dependency | Role |
|---|---|
| `SharpCpp.Model` (Ast namespace) | `BindingCompilation`, `RecordBinding`, `FunctionBinding`, `EnumBinding`, `FieldBinding`, `BindingType`, `BindingNode`, `ParameterBinding`, `VirtualMethodSlotBinding`, `RecordGenericInstantiationBinding`, `AccessorPropertyAnnotation`, `MetadataKeys`, etc. |
| `SharpCpp.Model.Utilities` | `CodeWriter` — the sole text-building utility used throughout |

### Dependents (consumers of this layer)

| Consumer | Role |
|---|---|
| `SharpCpp.Tool` | Calls `BindingOutputRenderer.Render()` and writes the resulting `GeneratedBindingSet` to disk. Owns the composition of the full pipeline. |
| Build system (CMake) | Compiles the generated `*.g.cs` (C#) and `*.g.cpp` (C++) files as part of the binding assemblies. |

### Runtime contracts (not code dependencies, but protocol invariants)

| Contract | Side | Details |
|---|---|---|
| `SharpCpp/Export.hpp` | Native | Provides the `SHARPCPP_EXPORT`, `arg_t<T>`, `ret_t<T>` macros/types |
| `SharpCpp/Marshaller.hpp` | Native | Provides `MarshallerInvoker::invoke`, `invoke_as`, `construct`, `destroy`, `get_field`, `set_field` |
| `SharpCpp/detail/MarshallerSupport.hpp` | Native | Supporting detail for marshaller dispatch |
| `SharpCpp.Support` (C#) | Managed | `NativeObject`, `NativeObjectRegistry`, `INativeObjectRegistration<T>`, `INativeInstanceCache`, `DefaultNativeInstanceCache`, `NativeObjectMetadata` — base class and runtime support |
| `System.Runtime.InteropServices` | Managed | `[LibraryImport]`, `[UnmanagedFunctionPointer]`, `[MarshalAs(UnmanagedType.I1)]`, `Marshal.GetFunctionPointerForDelegate` |

### Naming convention contract

Generated entry points follow the pattern `sharpcpp_e2e_{NativeName}_{kind}` where:
- Constructors: `sharpcpp_e2e_{RecordNativeName}_{ctorNativeName}`
- Instance methods: `sharpcpp_e2e_{RecordNativeName}_{methodNativeName}`
- Static methods: `sharpcpp_e2e_{RecordNativeName}_{methodNativeName}`
- Field getters: `sharpcpp_e2e_{OwningCppTypeName}_{fieldNativeName}_get`
- Field setters: `sharpcpp_e2e_{OwningCppTypeName}_{fieldNativeName}_set`
- Delete: `sharpcpp_e2e_{NativeName}_delete`
- Type ID: `sharpcpp_e2e_{NativeName}_type_id`
- Metadata: `sharpcpp_e2e_{NativeName}_metadata`
- Connect director: `sharpcpp_e2e_{NativeName}_connect_director`
- Callbase: `sharpcpp_e2e_{NativeName}_callbase_{methodNativeName}`
